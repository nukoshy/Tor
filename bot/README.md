# AI-администратор TÖR — WhatsApp-бот

Бот живёт на рабочем номере **+7 777 353 9587** и отвечает клиентам на казахском или русском:
меню и цены, залы, правила, приём заявок на бронь с записью в Google Calendar и уведомлением менеджера.

## Как это работает

```
Клиент в WhatsApp
      │
      ▼
   WAHA (шлюз, подключён как «связанное устройство» — телефон менеджера работает как раньше)
      │  вебхук
      ▼
  Этот сервис (Railway)
      │  ждёт 2–3 минуты: если менеджер уже ответил с телефона — бот молчит
      ▼
   LLM (DeepSeek/Qwen) + база знаний (knowledge/) + инструменты:
      ├─ check_availability → Google Calendar
      ├─ create_hold        → событие HOLD в календаре + уведомление менеджеру
      └─ notify_manager     → уведомление менеджеру («Избранное» номера)
```

Правила зашиты в промпт: никаких скидок, брони максимум за месяц, окончательное
подтверждение — только менеджер, депозита нет, свои фрукты нельзя (торт/кэнди-бар/алкоголь можно).
Голосовые расшифровываются (Whisper) и обрабатываются как текст.

## Локальный запуск

```bash
cd bot
npm install
cp .env.example .env   # заполнить LLM_API_KEY (DeepSeek: platform.deepseek.com)
npm run chat           # консольный чат с ботом без WhatsApp — проверка ответов
npm test               # сквозной тест каркаса (без ключей)
```

Меню бот берёт из сайта. После изменения меню в `../app.js`:

```bash
npm run sync-menu
```

## Развёртывание на Railway

Два сервиса в одном проекте:

**1. WAHA (шлюз WhatsApp)**
- New Service → Docker Image → `devlikeapro/waha`
- Volume: mount path `/app/.sessions` (чтобы сессия переживала рестарты)
- Переменные:
  - `WAHA_API_KEY` — придумай длинный ключ
  - `WHATSAPP_HOOK_URL` — `https://<домен-бота>/webhook?token=<WEBHOOK_TOKEN бота>`
  - `WHATSAPP_HOOK_EVENTS` — `message,message.any`
- Сгенерируй домен (Settings → Networking).

**2. Бот (этот код)**
- New Service → GitHub Repo, Root Directory = `bot`
- Volume: mount path `/data`, переменная `DATA_DIR=/data`
- Переменные из `.env.example`: `WAHA_URL` (домен WAHA), `WAHA_API_KEY`,
  `LLM_API_KEY`, `STT_API_KEY`, `GOOGLE_SA_JSON_B64`, `CALENDAR_ID`.

**Подключение номера (делает владелец, один раз):**
откры дашборд WAHA (`https://<домен-waha>/dashboard`), запусти сессию `default`,
на телефоне: WhatsApp → Настройки → Связанные устройства → отсканировать QR.
Телефон продолжает работать как обычно; бот видит переписку как WhatsApp Web.

## Google Calendar

1. Создай календарь «TÖR брони» в Google Calendar.
2. console.cloud.google.com → новый проект → включить Google Calendar API →
   Service Account → создать JSON-ключ.
3. `base64 -i ключ.json | tr -d '\n'` → в переменную `GOOGLE_SA_JSON_B64`.
4. В настройках календаря → «Доступ для отдельных пользователей» → добавить
   email сервисного аккаунта с правом «Внесение изменений».
5. `CALENDAR_ID` — из настроек календаря («Идентификатор календаря»).

Заявки создаются как события `HOLD · Зал · Имя · N гостей`; менеджер подтверждает
бронь и убирает `HOLD` из названия. Бот считает зал занятым, если на дату есть
событие с названием зала.

## Важно знать

- Шлюз работает как «связанное устройство» — это неофициальный способ, WhatsApp
  формально его запрещает. Для ответов на входящие риск бана низкий (никаких
  рассылок!), но он не нулевой. Первые дни обкатываем на запасном номере.
- Голосовые: бесплатный WAHA Core не отдаёт файлы медиа — бот вежливо попросит
  написать текстом. Чтобы бот понимал голосовые, нужен WAHA Plus (донат от $19,
  разово) или другой шлюз (Green API). Всё остальное работает на бесплатном Core.
- Если менеджер написал в чате — бот молчит там `HUMAN_COOLDOWN_MIN` минут (по
  умолчанию 60), потом снова подключается.
- Уведомления о заявках летят в «Избранное» (чат с самим собой) номера — задаётся
  переменной `ALERT_PHONE`.
